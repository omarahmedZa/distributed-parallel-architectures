Module 1 – Advanced Parallel Computer Architectures

Lecture 2 — Advanced Memory Architectures and Memory Hierarchy

Explain cache coherence and memory consistency mechanisms (including MESI), analyze NUMA architectures and shared-memory challenges, and reason about the performance and scalability trade-offs they impose.

Why this matters

In shared-memory parallel systems, correctness and performance hinge on how caches and memories behave under concurrent access. Coherence, consistency, and NUMA placement can enable programmability—or silently dominate runtime.

Prerequisites: Fundamentals — cache & memory hierarchy (locality, levels, coherence/consistency intuition).

Learning objectives

  • Describe cache coherence problems and how invalidation/update protocols address them.
  • Explain the MESI protocol states and transitions at an architectural level.
  • Characterize NUMA architectures and their performance implications.
  • Compare memory consistency models and identify shared-memory challenges and trade-offs.

Core ideas and mechanisms

Cache coherence

Multiple cores caching the same memory line can observe stale values after writes. Cache coherence provides rules ensuring a single-writer/multiple-reader invariant (or equivalent) per location so that reads eventually see writes appropriately. Two broad approaches exist: snooping protocols (common on small buses/interconnects, cores observe transactions) and directory-based protocols (a directory tracks sharers/owners, scalable to larger systems). Coherence operates at cache-line granularity and generates traffic (invalidations, writebacks, fetches).

MESI protocol

MESI is a widely used invalidation-based coherence protocol with four stable states per cache line:

StateMeaningImplication
M (Modified)Line present only in this cache and dirty (different from memory).Cache must supply/write back data on eviction or requests.
E (Exclusive)Line present only in this cache and clean (matches memory).Can transition to M silently on local write (no bus invalidate needed).
S (Shared)Line may be present in other caches; clean.Local write requires invalidating other sharers.
I (Invalid)Line not valid in this cache.Read/write misses must obtain a valid copy/ownership.

NUMA architectures

Non-Uniform Memory Access (NUMA) systems provide a single logical address space but with memory physically distributed across nodes/sockets; access latency and bandwidth depend on whether data is local or remote. NUMA improves memory bandwidth scaling versus a single centralized memory, but performance becomes placement-sensitive.

  • Benefits: higher aggregate memory bandwidth/capacity, scalable shared-memory organization.
  • Costs: remote access penalties, contention on inter-socket links, need for locality-aware allocation/scheduling.

Memory consistency models

Coherence makes per-location behavior sensible; memory consistency models specify ordering of reads/writes across different locations as observed by threads. Stronger models (e.g. sequential consistency intuition) simplify reasoning but restrict hardware/compiler reordering and can reduce performance; weaker/relaxed models allow more optimizations but require explicit synchronization/fences for ordering. Correct parallel programs rely on the model’s guarantees plus synchronization primitives.

Limitations, scalability, and shared-memory challenges

  • Coherence traffic: invalidations and data movement grow with sharing/write intensity and core count.
  • False sharing: unrelated variables on the same cache line cause needless coherence misses.
  • Synchronization cost: locks/atomics/barriers interact with coherence and ordering.
  • NUMA effects: poor placement yields remote accesses and bandwidth imbalance.
  • Programmability vs performance: relaxed models and NUMA tuning increase optimization burden.

Research problems

  • Scalable, low-latency coherence for many-core and heterogeneous systems.
  • Memory consistency/programmability interfaces that balance correctness and performance.
  • NUMA- and heterogeneity-aware data placement, migration, and profiling.
  • Reducing data-movement costs (near-memory processing, smarter caches/interconnects).

Recap and check for understanding

  • Coherence maintains a consistent view per memory location across caches; MESI captures modified/exclusive/shared/invalid states.
  • NUMA scales memory resources but introduces non-uniform access costs.
  • Consistency models govern cross-address ordering; stronger models simplify reasoning, weaker models enable performance but need synchronization.
  1. Why does a write to a cache line in Shared state require invalidations?
    Show answer

    Other caches may hold copies; invalidation (or update) ensures they do not read stale data and preserves coherence for that line.

  2. What is one symptom of poor NUMA locality?
    Show answer

    Higher average memory access latency and/or reduced effective bandwidth due to frequent remote-node accesses and interconnect contention.

Research Activities

Literature review — Paper 1

Citation M. S. Papamarcos and J. H. Patel, “A Low-Overhead Coherence Solution for Multiprocessors with Private Cache Memories,” in Proc. 11th Annual Int’l Symp. Computer Architecture (ISCA), 1984, pp. 348–354. DOI: 10.1145/800015.808204.

Core contribution: Introduces a low-overhead cache coherence approach (widely associated with the MESI-style invalidation protocol lineage) for multiprocessors with private caches.

Method/architecture: Uses cache-line states and invalidation-based coherence actions to maintain consistency of shared data while reducing unnecessary traffic compared to simpler schemes.

Key results: Demonstrates practical coherence with reduced overhead, influencing subsequent coherence protocol designs in shared-memory multiprocessors.

Limitations: Early protocol/model assumptions target the multiprocessor scales and interconnects of its era; scaling to many cores and complex hierarchies motivates directory schemes and protocol extensions.

Literature review — Paper 2

Citation L. Lamport, “How to Make a Multiprocessor Computer That Correctly Executes Multiprocess Programs,” IEEE Transactions on Computers, vol. C-28, no. 9, pp. 690–691, Sep. 1979. DOI: 10.1109/TC.1979.1675439.

Core contribution: Formulates the notion of sequential consistency, a foundational memory consistency model specifying that multiprocessor execution corresponds to some interleaving consistent with each processor’s program order.

Method/architecture: Provides a correctness condition/definition for memory system behavior in multiprocessors rather than a specific hardware implementation.

Key results: Establishes a clear, intuitive correctness baseline for reasoning about concurrent programs and memory ordering in shared-memory systems.

Limitations: Strict sequential consistency can constrain hardware/compiler optimizations and performance; many systems adopt relaxed models that require explicit synchronization to regain ordering guarantees.

Architecture comparison — Snooping vs Directory-based coherence

DimensionSnooping coherenceDirectory-based coherence
MechanismCaches observe (snoop) coherence transactions on a shared interconnectDirectory tracks which caches hold/share/own a line and sends targeted messages
AdvantagesConceptually simple; can be low-latency for small core countsScales to larger systems by avoiding global broadcast; targeted communication
LimitationsBroadcast/snoop bandwidth and ordering demands limit scalabilityDirectory storage/lookup overhead, added latency, and protocol complexity
Suitable use casesSmall multicore processors with shared bus/ring-like substratesLarge multicore/multi-socket and NUMA systems requiring scalable coherence

Case study — Stanford DASH / directory-coherent NUMA multiprocessor (research system)

What it is: The Stanford DASH project (early 1990s) was a research multiprocessor demonstrating scalable cache-coherent shared memory using a directory-based coherence approach across clusters of processors.

Architectural design: Combined bus-based snooping within clusters and a distributed directory protocol between clusters to maintain coherence over a scalable interconnect while providing a shared-memory abstraction.

How it addresses lecture challenges: Tackled the scalability limits of pure snooping by tracking sharers and sending point-to-point coherence messages, enabling coherent shared memory across more processors/nodes than snooping alone could efficiently support.

Observed strengths/limitations: Demonstrated feasibility and performance potential of scalable cache-coherent NUMA (CC-NUMA) designs; trade-offs included directory overhead, protocol complexity, and sensitivity to locality/remote-access latency—issues that remain central in modern NUMA systems.
