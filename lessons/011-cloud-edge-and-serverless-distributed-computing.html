Module 4 – Heterogeneous and Emerging Architectures

Lecture 11 — Cloud, Edge and Serverless Distributed Computing

Understand cloud HPC architectures, virtualization/containerization, distributed resource management, edge computing, and dynamic scaling (including serverless models), and evaluate their trade-offs for modern distributed workloads.

Why this matters

Cloud, edge, and serverless platforms reshape how distributed and parallel workloads are deployed and scaled. Architectural choices in virtualization, isolation, placement, and elasticity determine performance, cost, latency, and manageability.

Prerequisites: Lecture 4, Lecture 3, Lecture 9.

Learning objectives

  • Describe cloud HPC architecture and distributed resource management mechanisms.
  • Compare virtualization and containerization for isolation and deployment.
  • Explain edge computing motivations and architectural implications.
  • Analyze dynamic resource scaling and serverless execution trade-offs.

Core ideas and mechanisms

Cloud HPC architecture

Cloud HPC provides on-demand access to compute clusters, accelerators (Lecture 10), high-speed interconnects, and parallel storage. Architectures virtualize or bare-metal-provision resources, schedule jobs/instances across multi-tenant infrastructure, and offer elasticity (scale up/out). Performance depends on instance placement, network topology/bandwidth, storage throughput, and virtualization overheads.

Distributed resource management

Resource managers and orchestrators allocate compute, memory, storage, and network to tenants and workloads based on policies (fairness, priority, QoS, cost). They handle placement, autoscaling, failure recovery, and multi-tenancy isolation, often using hierarchical or decentralized control to scale (related to Lecture 8).

Virtualization and containerization

TechnologyIsolation/abstractionStrengthsLimitations
Virtual machines (VMs)Full hardware virtualization; guest OS per VMStrong isolation, OS flexibility, mature security boundariesHigher overhead (boot time, memory, I/O), less density
ContainersOS-level isolation sharing host kernel (namespaces/cgroups)Lightweight, fast startup, high density, portable imagesWeaker isolation boundary than VMs, kernel dependence

HPC and latency-sensitive services may use bare metal or tuned virtualization to reduce overhead and jitter; cloud-native services often favor containers and orchestration (e.g. Kubernetes-style systems).

Edge computing

Edge computing places computation/storage closer to data sources/users (devices, gateways, micro-datacenters) to reduce latency, bandwidth usage, and improve privacy/local autonomy. Architectures distribute processing across device–edge–cloud tiers, introducing heterogeneity, intermittent connectivity, and constrained resources.

Serverless and dynamic resource scaling

Dynamic scaling adjusts resources to load (horizontal/vertical autoscaling). Serverless/FaaS abstracts server management: users deploy functions triggered by events; the platform provisions, scales (including to zero), and bills per execution. Benefits include elasticity and operational simplicity; challenges include cold starts, execution limits, state management, and communication overheads for tightly coupled parallel workloads.

Architectural design decisions and trade-offs

  • Placement: edge for low latency/locality vs cloud for capacity/aggregation.
  • Isolation mechanism: VMs for strong isolation vs containers for density/speed vs bare metal for performance predictability.
  • Elasticity model: reserved/provisioned for predictability vs autoscaled/serverless for variable demand and cost efficiency.
  • State and coupling: serverless suits stateless/event-driven tasks; tightly coupled HPC/low-latency communication favors persistent clusters.

Limitations and scalability

  • Virtualization/network virtualization can add latency/jitter and reduce HPC efficiency.
  • Multi-tenancy introduces interference/noisy-neighbor effects.
  • Edge environments face resource constraints, heterogeneity, and unreliable connectivity.
  • Serverless cold starts, time/memory limits, and data locality hinder long-running or tightly coupled parallel jobs.

Research problems

  • High-performance, low-jitter cloud networking and virtualization for HPC/AI workloads.
  • Resource management and scheduling across cloud–edge–device continuum.
  • Programming models for stateful, data-intensive, and latency-sensitive serverless/edge applications.
  • Energy, cost, and QoS-aware placement and scaling.

Recap and check for understanding

  1. Why is edge computing useful for latency-sensitive applications?
    Show answer

    Processing data closer to sources/users reduces round-trip latency and network bandwidth usage compared to sending all data to distant cloud resources.

  2. What is one reason serverless is often a poor fit for tightly coupled parallel HPC jobs?
    Show answer

    Cold starts, execution limits, ephemeral/stateless environments, and high/variable communication overheads make sustained low-latency coordination and data locality difficult.

Research Activities

Literature review — Paper 1

Citation M. Armbrust, A. Fox, R. Griffith, et al., “A View of Cloud Computing,” Communications of the ACM, vol. 53, no. 4, pp. 50–58, Apr. 2010. DOI: 10.1145/1721654.1721672.

Core contribution: Provides a foundational characterization of cloud computing, its service models, opportunities, and key technical/economic challenges.

Method/architecture: Synthesizes cloud properties (elasticity, pay-as-you-go, resource pooling) and analyzes obstacles and research/engineering issues.

Key results: Clarifies why cloud models enable scalable, on-demand computing and identifies challenges such as availability, data lock-in, performance unpredictability, and security.

Limitations: Early perspective; technologies (containers, serverless, specialized accelerators, edge integration) have evolved, though core trade-offs remain relevant.

Literature review — Paper 2

Citation M. Satyanarayanan, “The Emergence of Edge Computing,” Computer, vol. 50, no. 1, pp. 30–39, Jan. 2017. DOI: 10.1109/MC.2017.9.

Core contribution: Articulates the motivations, architectural vision, and challenges of edge computing as a complement to cloud computing.

Method/architecture: Discusses edge/cloudlets, latency/bandwidth/privacy drivers, and system issues in distributing computation closer to data sources.

Key results: Frames edge computing as essential for latency-sensitive and bandwidth-intensive applications, outlining requirements for infrastructure and software support.

Limitations: High-level vision; deployment specifics vary widely, and challenges in management, security, heterogeneity, and programming models continue to be active research areas.

Case study — AWS ParallelCluster / cloud HPC environments

What it is: AWS ParallelCluster is an open-source cluster management tool for deploying and managing HPC clusters in the AWS cloud, representative of cloud-based HPC architectures.

Architectural design: Automates provisioning of compute instances (including accelerators), networking, shared storage, and schedulers (e.g. Slurm) with elastic scaling and integration into cloud resource management services.

How it addresses lecture challenges: Enables on-demand, dynamically scalable HPC resources and simplifies distributed cluster setup, bringing virtualization/orchestration and elasticity to parallel workloads.

Observed strengths/limitations: Offers flexibility, rapid provisioning, and access to diverse hardware; performance for tightly coupled workloads can be affected by instance placement, network performance, virtualization overheads, and cost—requiring tuning compared to dedicated supercomputers (characteristics typical of cloud HPC deployments).
