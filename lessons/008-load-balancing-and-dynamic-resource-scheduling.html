Module 3 – Advanced Parallel Processing and Optimization

Lecture 8 — Load Balancing and Dynamic Resource Scheduling

Compare static and dynamic load balancing, task scheduling, work stealing, and resource allocation strategies, and evaluate their impact on performance and scalability in distributed environments.

Why this matters

Parallel speedup is limited by the slowest participant. Load imbalance and poor scheduling waste resources and amplify synchronization/communication delays; effective balancing and scheduling are essential for scalable performance.

Prerequisites: Fundamentals (speedup/efficiency), Lecture 7 (decomposition/irregularity).

Learning objectives

  • Differentiate static and dynamic load balancing approaches.
  • Explain task scheduling models and work stealing.
  • Analyze resource allocation and scheduling strategies in distributed environments.
  • Assess trade-offs among overhead, balance quality, locality, and scalability.

Core ideas and mechanisms

Static load balancing

Static balancing assigns work before execution based on known costs/structure (e.g. block/cyclic distributions, precomputed partitions). It has low runtime overhead and can preserve locality, but performs poorly when workloads are unpredictable, irregular, or time-varying.

Dynamic load balancing

Dynamic balancing adjusts assignments at runtime in response to observed load/imbalance. Strategies include centralized managers (simple global view but bottleneck) and distributed/hierarchical schemes (scalable but more complex). It handles irregularity and variability at the cost of monitoring, migration, and coordination overhead.

Task scheduling and work stealing

Task schedulers map runnable tasks to workers considering dependencies, priorities, and locality. Work stealing is a distributed dynamic strategy: each worker maintains a local deque of tasks; idle workers (“thieves”) steal tasks from others (“victims”). This provides automatic load balancing with good locality (workers execute their own tasks first) and provably good behavior for well-structured parallel computations.

Resource allocation and scheduling in distributed environments

Distributed schedulers allocate CPU, memory, bandwidth, accelerators, and nodes to jobs/tasks across clusters or federated systems. Policies consider fairness, priority, deadlines/QoS, data locality, and utilization. Architectures range from centralized (e.g. classic cluster managers) to two-level/hierarchical and fully decentralized designs to improve scalability and resilience.

Worked example: imbalance impact on speedup

With p=4 workers and total parallel work equivalent to 100 time units evenly divided, ideal T=25. If dynamic imbalance leaves workers finishing at 20, 20, 25, 35, then T(p)=35 (the straggler dominates), giving S=100/35≈2.86× and E≈71.4% instead of 4×/100%. Reducing imbalance (better decomposition, dynamic balancing, or stealing) directly improves efficiency.

Limitations and scalability

  • Balancing overhead (migration, synchronization, metadata) can outweigh benefits for fine-grained tasks.
  • Locality-aware balancing is harder: moving work may move or invalidate data.
  • Distributed environments add heterogeneity, failures, and variable communication costs.

Research problems

  • Scalable, locality- and heterogeneity-aware scheduling for exascale and cloud-edge systems.
  • Online learning/adaptive policies for unpredictable workloads.
  • Co-scheduling compute, data movement, and accelerators/energy constraints.

Recap and check for understanding

  1. Why can static load balancing fail on irregular graph workloads?
    Show answer

    Work per partition may vary unpredictably (e.g. skewed degrees), so preassigned loads become unbalanced at runtime.

  2. What is a key advantage of work stealing over centralized dynamic balancing?
    Show answer

    It distributes balancing decisions among workers, avoiding a single scheduler bottleneck and scaling better while preserving local-task locality.

Research Activities

Literature review — Paper 1

Citation R. D. Blumofe and C. E. Leiserson, “Scheduling Multithreaded Computations by Work Stealing,” Journal of the ACM, vol. 46, no. 5, pp. 720–748, Sep. 1999. DOI: 10.1145/324133.324234.

Core contribution: Provides a randomized work-stealing scheduling algorithm and theoretical analysis for executing multithreaded computations efficiently.

Method/architecture: Models parallel computations and analyzes time/space/communication bounds when idle processors steal tasks from others’ deques.

Key results: Shows work stealing achieves expected time close to optimal and good space/communication bounds, establishing it as a foundational scheduling strategy.

Limitations: Guarantees rely on model assumptions; practical performance depends on task granularity, memory hierarchy/locality, and implementation overheads in real systems.

Literature review — Paper 2

Citation M. Isard, V. Prabhakaran, J. Currey, U. Wieder, K. Talwar, and A. Goldberg, “Quincy: Fair Scheduling for Distributed Computing Clusters,” in Proc. ACM SOSP, 2009, pp. 261–276. DOI: 10.1145/1629575.1629601.

Core contribution: Proposes a cluster scheduling framework that balances fairness and data/computation locality using a flow-based optimization approach.

Method/architecture: Models scheduling decisions as a min-cost flow problem over tasks, nodes, and data locations to compute assignments efficiently.

Key results: Demonstrates improved locality and fairness trade-offs compared to simpler queue-based schedulers in distributed data-processing clusters.

Limitations: Centralized/global optimization can face scalability and responsiveness challenges at very large or highly dynamic scales; assumptions may not capture all workload heterogeneity.

Case study — Cilk runtime (work-stealing scheduler)

What it is: Cilk is a parallel programming language/runtime (originating at MIT) that uses work stealing to schedule fine-grained tasks on shared-memory multicore systems.

Architectural design: Programmers express parallelism (e.g. spawn/sync constructs) while the runtime maintains per-worker deques and performs steals when workers become idle, balancing load dynamically.

How it addresses lecture challenges: Provides scalable dynamic load balancing with good locality and low overhead for many divide-and-conquer/task-parallel workloads, reducing programmer burden for scheduling.

Observed strengths/limitations: Strong performance and simplicity for suitable task-parallel programs; effectiveness depends on sufficient parallelism/granularity and can be constrained by memory locality, synchronization, and extension to distributed/heterogeneous environments.
